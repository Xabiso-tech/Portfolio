WeConnect

Team of 4 My role: delivery & tracking 2026

A B2B marketplace where small businesses order stock from wholesalers. It is the largest thing I have worked on: 608 commits across 24 tables, and by far the most code I have had to read before I could change anything.

  • My work: the delivery and logistics layer, end to end. I wrote the orders, deliveries and payments back end, the GPS tracking API, and the front-end pages that render them.
  • The delivery query joins orders, buyers, suppliers and payments in one pass, returning pickup and destination coordinates, route distance and estimated duration for the map.
  • Every query is parameterised through mysql2 placeholders, never string concatenation, and the model layer is split from routes and controllers.
  • Location setup as its own step: coordinates and a route snapshot are confirmed and saved before a delivery is dispatched.
  • Connected the Vue 3 front end to the real API, replacing the sample data the pages had been reading from, then added the cart and reviews endpoints to support that.
  • Connected the Leaflet map to the latest recorded delivery position so buyers can see where the courier is.

Stack: Express 5, MySQL over SSL, jsonwebtoken, bcryptjs, multer, cors, dotenv · Vue 3, Vite, vue-router, Vuex, Leaflet, SweetAlert2. The database sits behind a managed host, so the connection verifies a CA certificate rather than trusting the network. No real credentials are in the repository, only .env.example placeholders. Team: Zanda Kumsha, Zahra Moerat, Phelisa Fani and me.

HR Tech Solutions

Team of 4 My role: back end 2026

A human resources system for employee records, performance reviews, attendance, time off and payroll. Four developers built it together, and it is the project that moved me from front-end exercises into real back-end work.

  • My work: built the employee and performance review back end, then rewired those front-end pages to read from it.
  • Express routes, controllers and models kept in separate layers so the database could change without touching the HTTP layer.
  • Queries written against mysql2 with values passed as parameters, rather than concatenated into the query string.
  • JWT sign-in alongside middleware that checks the bearer token before a protected route runs.
  • Handled the awkward status codes properly: 400 for bad input, 401 and 403 for who you are and what you may touch, 404 for nothing there.
  • Worked on a feature branch and merged into a shared develop branch alongside three other developers.

What is deployed: the front end. The Express and MySQL layer described above is in the repository, but the live site runs against local sample data, so the sign-in and the screens are a demo rather than a working service.

Stack: Express 5, MySQL, jsonwebtoken, bcrypt, cors, dotenv · HTML, CSS, vanilla JavaScript. The repository includes a schema.sql and an entity relationship diagram. Team: Nikita Muller, Rushin, Rasool and me.

Premium Car Products

HTML Bootstrap 5.3 Multi-page

AutoVault, a four-page catalogue for performance parts, was my Bootstrap study: grid, navbar, cards, badges and a carousel, wired together with utility classes instead of custom CSS. Reading it back years later, the useful part was seeing how much a framework carries for you, and where it stops.

  • Four linked pages: home, catalogue, about and contact
  • Carousel, navbar, cards, badges and alerts built from Bootstrap components
  • Re-toned onto the portfolio's graphite palette with an override stylesheet, so the exercise still reads as itself
  • Fixed eight “View Item” links that went nowhere, unclosed div tags that spilled past the grid, a 500+ claim the catalogue could not support, and a carousel that auto-rotated with no controls

HTML & CSS Forms & tables

A form and schedule built while I was still learning how a browser sends information. It had a malformed email input and table rows sitting outside the table body, which is exactly the kind of thing you only catch by reading the DOM rather than assuming it is fine.
