HR Tech Solutions

Team of 4 My role: back end 2026

A working human resources system for employee records, performance reviews, attendance, time off and payroll. Four developers built it together, and it is the project that moved me from front-end exercises into real back-end work.

  • My work: built the employee and performance review back end, then rewired those front-end pages to read from it.
  • Express routes, controllers and models kept in separate layers so the database could change without touching the HTTP layer.
  • Queries written against mysql2 with values passed as parameters, rather than concatenated into the query string.
  • JWT sign-in alongside middleware that checks the bearer token before a protected route runs.
  • Handled the awkward status codes properly: 400 for bad input, 401 and 403 for who you are and what you may touch, 404 for nothing there.
  • Worked on a feature branch and merged into a shared develop branch alongside three other developers.

Stack: Express 5, MySQL, jsonwebtoken, bcrypt, cors, dotenv · HTML, CSS, vanilla JavaScript. The repository includes a schema.sql and an entity relationship diagram. Team: Nikita Muller, Rushin, Rasool and me.

Smaller builds with narrower jobs. Each one exists because I hit a specific problem I did not understand yet, and the fastest way through it was to build the thing badly and then fix it.

My Gallery

HTML & CSS Layout & filtering

A responsive image gallery built to get a handle on grid layout, alignment and filtering. The version here is the one where I finally stopped hard-coding image paths and got them right at every nesting level.

  • Filterable categories with the active state tracked in CSS
  • Intrinsic image dimensions to stop the page jumping while loading
  • Lazy loading and async decoding on every image
  • Relative paths that survive being served from a sub-path

Premium Car Products

HTML Bootstrap 5.3 Multi-page

AutoVault, a four-page catalogue for performance parts, was my Bootstrap study: grid, navbar, cards, badges and a carousel, wired together with utility classes instead of custom CSS. Reading it back years later, the useful part was seeing how much a framework carries for you, and where it stops.

  • Four linked pages: home, catalogue, about and contact
  • Carousel, navbar, cards, badges and alerts built from Bootstrap components
  • Re-toned onto the portfolio's graphite palette with an override stylesheet, so the exercise still reads as itself
  • Fixed eight "View Item" links that went nowhere, unclosed div tags that spilled past the grid, a 500+ claim the catalogue could not support, and a carousel that auto-rotated with no controls

Booking Form

HTML & CSS Forms & tables

A form and schedule built while I was still learning how a browser sends information. It had a malformed email input and table rows sitting outside the table body, which is exactly the kind of thing you only catch by reading the DOM rather than assuming it is fine.

  • Inputs tied to their labels, with the right input types and autocomplete
  • A select for subject and a message area
  • A schedule table with row headers and a scrollable container
  • Both bugs above found and fixed; the form is honestly labelled as a front-end study with nothing behind it
